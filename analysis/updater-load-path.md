# SQUID v1.13: how firmware reaches the unit, and can a modified image load?

Static analysis only (Mach-O updater asm in `updater-selected.asm`, objdump of the Mach-O at 0xF730, PE strings, byte scans of the .bin). Nothing was executed; no device touched. Confidence: H/M/L. "Observed" = read from bytes/asm; "Inferred" = my interpretation.

## Verdict
A modified image looks **feasible at the host side**: no signature, hash, encryption or compression is visible anywhere in updater or payload. The only host-side gate is a CRC-16 that anyone can recompute. Whether the **device** rejects an altered image is not established (device-side USB handler not yet traced). Brick risk is real: the transfer overwrites offset 0 (reset vector/bootstrap) and no separate ROM bootloader is evidenced.

## What a modified image must satisfy (inferred from items 7-10)
Size exactly 2,097,152; version text at 0x1D0000 in the allowed pattern; date word at 0x1DFFFC plausible (change it, or not: equal date skips F1, which is useful for an app-only patch confined to 0x90000-0x1D0000); CRC-16/0x1021 (init 0, MSB-first, no final xor) recomputed over bytes 0..0x1FFFFD and stored little-endian at 0x1FFFFE; keep the loader/bootstrap structure intact. Updater-side, nothing else is checked. A patch could also bypass the vendor tool entirely by speaking the HID protocol (items 5-6), but its op semantics must be pinned first.

## Unknowns (priority order)
1. Device-side handler for kinds 0xF0-0xF7 (USB HID report parser in the firmware): does it validate address ranges, refuse protected regions such as 0x0-0x20000, check the byte-sum, a version/date, or anything cryptographic? This is the real answer to "will the unit accept it". Needs a Ghidra pass on the HID endpoint callback near the descriptors (0xF5330/0xF552C app, 0x52398 alt), anchored on the 64-byte report.
2. Exact semantics of ops 5, 8, 0xA and reply 0x83-0x85 and 0x81 subcodes (error ids 0xE31, E33-E35, E41).
3. Whether the flash is write-protected for the boot area and whether the 0x1D0FFC word is a boot-bank selector; what recovery exists if the application bank is corrupt (does the alternate bank boot and still speak HID, as the descriptor copies suggest?).
4. Whether the unit must be in a special state (item 4 says none seen); and what the "Push OK Button" step does (host dialog only?).
5. Windows path (`toraizsquidhid.dll`, PID_0140/0143 strings) not diffed against Mac; assumed same protocol (same source tree `toraiz_is1`).
6. Exact MCU/flash type and sector size (needed to size erase ops).
